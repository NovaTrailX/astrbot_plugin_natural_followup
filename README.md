# 自然续聊

在 QQ 群里，叫一次机器人之后，往往还要补一句、改个条件，或者接着追问。自然续聊让这些消息在一小段时间内直接接上，省去每句都重新 @ 的麻烦。

插件沿用当前会话的聊天模型和人格，在本地筛选是否接话、合并同一人的连续短消息。其他群友也可以顺着刚才的话题加入；没有明显关联的插话通常会被忽略。自动接话交给主模型后，模型仍可以选择沉默。

当前发布版本为 **v0.1.3**。支持 AstrBot `>=4.28.1,<4.30.0`、OneBot v11 的 QQ 群和 AstrBot 内置 Agent。已验证 4.28.1 与 4.29.3；私聊和第三方 Agent 不在接管范围内。

## 安装后先配这两项

在 AstrBot 插件市场搜索「自然续聊」，或通过仓库地址安装：

```text
https://github.com/NovaTrailX/astrbot_plugin_natural_followup
```

打开插件配置，填写「启用群列表」。每项的格式是 `平台实例ID:GroupMessage:群号`，平台实例 ID 可以在 AstrBot 的消息平台配置中找到。空列表表示没有任何群启用续聊。

如果希望直接喊名字唤醒，再填写「额外称呼」，例如 `小助手`。默认没有预设称呼；不填也可以继续使用 AstrBot 原有的 @、引用和唤醒前缀。

下面是配置片段。把 `qq-main` 和 `<群号>` 换成自己的值，再合并到已有配置中：

```json
{
  "enabled_groups": ["qq-main:GroupMessage:<群号>"],
  "aliases": ["小助手"]
}
```

保存配置后重载插件，让新规则重新读取。首次试用时，可以先只开一个群：@ 机器人问一句，等它回答后，再发一句不带称呼的追问。

插件按群共享会话设计。若 AstrBot 为每位群成员分配独立会话，不同会话 ID 会触发窗口清理，续聊可能被打断。建议同时启用 AstrBot 原生的发送者标识，让模型分清是谁在接话。

如果已有其他自动续聊或昵称唤醒功能，请先检查它们与本插件的触发范围。多个入口同时开启，自动回复会叠加；本插件不会替你调整其他插件的设置。

## 一段对话怎样接下去

下面用虚构群友和片名演示默认配置。例子里只有一段相关话题，接话都发生在有效窗口内。

```text
甲：@机器人 聊聊电影《星河》。
机器人：你想聊剧情，还是画面？
甲：轨道电梯那段。
机器人：那一段可以聊聊材料强度的问题。
乙：轨道电梯用的是什么材料？
机器人：……
丙：今晚吃什么？
（丙没有续聊资格，也没有唤醒机器人，本插件不会因为这句闲聊接话。）
```

### 本人追问

用 @、引用机器人、原生唤醒前缀或额外称呼开始对话后，机器人成功发出回答，就会给这位发送者留下默认 **90 秒**的续聊窗口。在窗口内，追问、补条件、纠正对象，都可以直接发送。

每次成功发送回答后重新计算这 90 秒。模型沉默、发送失败、回答被后来的消息取代，都不会延长窗口。时间到了，再正常唤醒一次即可。

额外称呼匹配句首，或句末单独出现的名字。例如 `小助手你怎么看`、`你怎么看，小助手` 都能触发；`我昨天看到了小助手的消息` 这种句中提及不会唤醒。

### 群友接话

其他群友可以在机器人最近一次相关回答后的默认 **20 秒**内加入，但文字必须对得上一段明确的话题。接话可能通过以下方式被识别：

- 以「我也」「其实」「确实」等说法承接，并带有相关话题词。
- 连续复现至少三个字的相关内容，例如「轨道电梯」。
- 提出问题，并至少匹配两个内容词，例如话题里已有「星河」和「结局」，再问「星河结局是什么」。

两个分散的词偶然重合还不够。例如刚聊过「材料强度」，另一人说「材料交了，强度训练也结束了」，不会因此加入。同时对得上多段对话时，也会放过这次插话，避免串线。

加入者收到回答后，会有自己的续聊窗口，但免唤醒只用于继续刚才的话题。「这种材料能做出来吗」「有多贵」「再详细说说」可以接着问；突然改问晚饭，通常会在本地被忽略。要换话题，重新 @ 或喊配置的称呼。

这套筛选依靠文字关联，不额外调用一个判断模型。没有明显关联词的改述可能接不上，重新唤醒就好。通过本地筛选后，主模型仍会判断这句话是否值得接，也可能选择沉默。

### 短消息与图片

同一人连续拆开发的短消息，会先合成一批再交给原生处理链。默认从最后一条消息到达起等 **1.2 秒**，从这一批开始最多等 **3 秒**。因此消息刚发完时，稍等一下是正常现象。

合并上限为 8 条消息或 8000 字符。单条消息本身已经超长时，单独处理并保留原文。不同群友的消息不会合在同一批。

启用图片续聊后，窗口内的图片也可以不带唤醒词。图片交给当前聊天模型，沿用 AstrBot 的多模态能力，因此当前模型需要支持图片。生成过程中补来的图片，会留到下一轮多模态请求。

如果回复只有图片、没有文字，图片会照常发送，但不会靠这次纯图片回复重新计算文字续聊窗口。

通过相关插话加入的人，窗口内发图仍可能调用主模型；图片是否跑题由模型判断，不能按文字筛选的零调用规则理解。

### 收尾与结束

「好」「嗯」「收到」等简短收尾通常不会继续叫模型。如果机器人刚才在问「要不要举个例子」，同样一个「好」仍可能算有效回答。

默认结束短语有「不用回了」「先这样」「不用回复了」「先不聊了」。去掉首尾空白、末尾标点及前置的配置称呼后精确匹配，只关闭说话者自己的窗口，不影响其他群友。

## 机器人还在生成时，可以补充吗

可以。后来补的文字优先交给 AstrBot 原生的同用户追加机制。插件不会为了重新合并消息而主动重跑已经完成的工具；没有被当前请求吸收的内容会进入下一批。

新消息到达后，尚未交给平台发送的旧答案可能被抑制，避免先答旧问题、再答纠正后的问题。已经发出去的消息无法靠这项机制撤回。

插件会为自己接管的回答关闭流式输出，让发送前的纠正仍有机会生效。工具状态提示和分段回复继续使用 AstrBot 的设置；这些功能开启后，群里仍可能看到中间状态消息。

本插件会将未送达或被抑制的最终回答标记为不保存，并只在确认发送成功后延长窗口。其他插件若提前保存或自行发送消息，仍需单独检查它们的行为。对 OutputPro 的折叠转发，插件会在发送成功后使用其提供的正文信息更新续聊状态；OutputPro 不是安装前提。

## 配置参考

时间单位均为秒。未开放为配置的内部上限保持固定。

| 配置键 | 默认值 | 范围与作用 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关闭后使用 AstrBot 原生触发方式。 |
| `enabled_groups` | `[]` | 启用群的完整标识列表，空列表不启用任何群。 |
| `aliases` | `[]` | 额外称呼，匹配句首或句末独立称呼。 |
| `idle_seconds` | `90` | 10–300；从上次成功发送回答起计算本人的空闲超时。 |
| `join_seconds` | `20` | 0–60，且不大于 `idle_seconds`；`0` 关闭群友自动加入。 |
| `debounce_seconds` | `1.2` | 0–3；同一人最后一条消息到达后的合并等待。 |
| `max_wait_seconds` | `3` | 0–10，且不小于 `debounce_seconds`；连续发消息时的最长收集时间。 |
| `image_followup` | `true` | 允许窗口内的图片续聊；需要当前模型具备图片能力。 |
| `user_batches_per_minute` | `8` | 1–120；每位用户每分钟可接受的自动候选批次。 |
| `group_batches_per_minute` | `20` | 1–120；每群每分钟可接受的自动候选批次。 |
| `join_batches_per_window` | `2` | 1–120；每群在 `join_seconds` 长的滑动窗口内，可接受的新加入候选批次。 |
| `end_phrases` | `不用回了`、`先这样`、`不用回复了`、`先不聊了` | 精确结束本人的窗口，支持自定义短语。 |
| `debug_stats` | `false` | 开启触发原因、条数和耗时等调试统计。 |

每用户、每群的批次限额约束自动接话，显式 @、额外称呼和原生唤醒不占这些额度。内存最多维护 128 份用户状态，同一用户最多有 4 批未结束的任务；达到容量上限时，显式唤醒仍可回到 AstrBot 原生处理。

配置中的非法类型、超出范围的数值，以及互相冲突的等待时间，会直接报错。群里消息较密时，可以缩短群友加入窗口，或将 `join_seconds` 设为 `0`，只保留本人续聊。想多合并几条拆开的句子，可以适当增加 `debounce_seconds`，同时留意回复开始得也会更晚。

## 原有命令、人格和其他插件

已匹配的命令与固定功能先执行，不会并入续聊，也不会因为执行命令而延长窗口。`/reset`、`/new` 等操作成功并触发会话清理后，会清除本群对应的短时状态。

带唤醒前缀但没有匹配到命令、最后仍交给聊天模型的消息，继续按原生唤醒处理。前缀以 AstrBot 自己的配置为准，`/`、`#` 只是常见例子。

正常回答继续沿用当前会话的人格和聊天模型。场景感知、长期记忆、主动插话等插件仍各自工作，它们的触发不等于本插件也打开了续聊窗口。明确 @ 或引用别人时，本插件通常不接话；同时使用配置的额外称呼或原生唤醒时，仍可按显式请求处理。

## 数据和调用开销

续聊资格、话题关联及短时消息信息保存在进程内存中。重启、重载插件或切换会话后，原窗口失效；异常停留约 10 分钟的批次也会被清理。插件不另外建立长期记忆库，但 AstrBot 原有的聊天历史、媒体文件和其他插件的数据仍按各自规则保存。

被接纳的消息、图片和必要的发送者标识会随原生请求交给当前配置的模型。若未启用 AstrBot 原生发送者标识，插件会为接管的请求补充发送者账号和昵称，帮助模型区分群友。自动接话还会附加临时规则，要求模型在无关或收尾时保持沉默；这段规则不作为用户原话写入历史。

本地筛选不通过的消息，不会由本插件调用模型。通过筛选后，原生聊天及工具调用按现有配置运行；即使模型最后选择沉默，也已经产生模型请求。短消息合并能减少部分拆句请求，但不能据此保证整群用量一定下降。

调试统计不写消息正文、群号、用户账号或凭据。空回复等异常日志可能带消息编号，AstrBot 和其他插件也可能有自己的日志；分享排障材料前仍应检查内容。

## 接不上话时，从这里查

| 现象 | 可以先检查 |
| --- | --- |
| 安装后完全没有续聊 | 启用群列表是否填写了完整的平台实例 ID 和群号；保存配置后是否重载。 |
| @ 能答，喊名字没反应 | 额外称呼默认为空，需要自行填写；句子中间提到名字不会唤醒。 |
| 本人能追问，别人插话不接 | 群友加入窗口是否已过、是否设为 `0`；文字是否能唯一关联到一段对话。 |
| 发完消息要等一下 | 检查短消息合并等待。默认会从最后一条消息到达起再等 1.2 秒。 |
| 图片没有被理解 | 当前聊天模型是否支持图片，AstrBot 自身的图片链路是否正常。 |
| 聊着聊着窗口失效 | 是否刚切换会话、重载插件、超时，或最近一次回答没有成功送达。 |
| 自动接话偶尔沉默 | 可能被本地规则、批次限额或主模型的沉默判断过滤；重新显式唤醒可以确认。 |

显式唤醒遇到空输出或完整的沉默标记时，插件会给出固定提示「我刚才没有生成出回复，你可以再问一次。」，不为这条提示追加模型请求。普通续聊仍允许沉默；网络、提供商或平台发送异常由相应处理链负责，不能用这条提示覆盖所有失败。

## 开发与测试

规则与响应边界测试不需要安装 AstrBot，也不需要连接 QQ 或模型：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q .
```

`tests/integration_pipeline.py` 使用真实 AstrBot 处理链，把模型和 QQ 发送端替换为测试实现。脚本使用虚构群、发送者与通用称呼，并为测试设置较短的等待时间；这些数值不代表默认配置下的响应速度。

运行集成脚本需要现成的 AstrBot 环境，将插件放入独立测试数据目录的 `data/plugins/astrbot_plugin_natural_followup` 下，并把 `ASTRBOT_ROOT` 指向该独立目录。脚本会写测试配置和虚构会话，因此不能使用正在运行的实例数据。未设置 `ASTRBOT_ROOT` 时会拒绝运行。

测试覆盖命令避让、连续追问、相关插话、发送前纠正、发送失败及媒体生命周期；真实 QQ 客户端显示、多模态理解质量和联网工具结果仍需按具体环境验证。

发布前核对代码、配置说明与版本声明，确认工作区中没有本机配置、聊天记录或凭据。GitHub 推送和市场更新分别核验：市场若提供固定版本下载包，应检查实际下载包的版本、提交和兼容范围，不能只看仓库 `main` 已经更新。

## 停用

关闭总开关，或清空启用群列表并重载插件，新的续聊就会停止。重载或卸载会释放等待中的批次，不删除已有聊天记录，也不修改人格或聊天模型。此前手动关闭过的其他唤醒功能，需要按自己的使用安排恢复。
