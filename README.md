# 自然续聊

QQ 群里，有人用 @、引用、唤醒前缀或配置的称呼把机器人叫起来之后，短时间内可以直接把后半句补上。插件在本地决定是否交给原来的主模型；正常回答沿用原来的人格。显式唤醒遇到空输出或完整沉默标记时，会给出固定失败提示「我刚才没有生成出回复，你可以再问一次。」；普通续聊允许沉默。不额外接一个判断模型，也不建记忆库。

当前版本 v0.1.3，MIT 许可证。

```text
甲：小助手你怎么评价
机器人：评价什么？
甲：电影《星河》最后一幕
机器人：……
乙：轨道电梯材料是什么
机器人：……（接得上就答，接不上就沉默）
丙：今晚吃火锅吗
（不因此调用模型）
```

## 适用

AstrBot `>=4.28.1,<4.30.0`，OneBot v11 的 QQ 群，内置 Agent。已验收 4.28.1 与 4.29.3；私聊和第三方 Agent 不接管。

在插件市场或下面的仓库安装：

```text
https://github.com/NovaTrailX/astrbot_plugin_natural_followup
```

安装后先填「启用群列表」。格式是 `平台实例ID:GroupMessage:群号`，例如 `qq-main:GroupMessage:123456789`。平台实例 ID 在 AstrBot 的消息平台配置里。列表为空时，哪个群都不会启用。

「额外称呼」默认也是空的。按自己的机器人来填，比如 `小助手`。句首的「小助手你怎么看」，以及句末单独的称呼，可以叫醒；句子中间顺便提到这个名字，不会。

建议继续用群共享会话，并打开原生的发送者标识。没开标识时，插件会给自己接管的请求补上发送者 ID 和昵称。模型和人格沿用这个群原来的配置。图片也沿用 AstrBot 已有的多模态，不另配识图模型。

如果原来已经有自动续聊或昵称唤醒，先停掉重复的那一个入口。两套一起开，会把自动回复的范围叠大。这个插件不会去改其他插件的配置。

## 配置

| 配置键 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 总开关。关掉后回到原生触发。 |
| `enabled_groups` | `[]` | 按平台实例限定群。空列表不启用任何群。 |
| `aliases` | `[]` | 额外称呼。只匹配句首，或句末单独出现的称呼。 |
| `idle_seconds` | `90` | 本人空闲超时，10–300 秒。从最后一次真正发出去的回答算起。 |
| `join_seconds` | `20` | 群友加入窗口，0–60 秒，不能大于本人超时。`0` 关闭别人自动加入。 |
| `debounce_seconds` | `1.2` | 同一个人停手之后再合并提交，0–3 秒。 |
| `max_wait_seconds` | `3` | 最长收集时间，0–10 秒，不能小于上面的合并等待。 |
| `image_followup` | `true` | 窗口内的图片可以不带唤醒词。生成过程中补的图，要等这一轮结束再进下一次多模态请求。 |
| `user_batches_per_minute` | `8` | 每人每分钟的自动候选上限，1–120。显式 @、称呼和原生唤醒不占这个额度。 |
| `group_batches_per_minute` | `20` | 每群每分钟的自动候选上限，1–120。 |
| `join_batches_per_window` | `2` | 每个加入窗口里，新群友候选的上限，1–120。 |
| `end_phrases` | 不用回了、先这样、不用回复了、先不聊了 | 精确结束本人的窗口。忽略首尾空白、末尾常见标点和前置称呼。 |
| `debug_stats` | `false` | 记录原因、条数和耗时。不记录正文、账号或凭据。 |

非法值会直接报错，不会悄悄放宽。消息很密的群，可以把加入窗口改成 `0` 或 `10`，每群自动候选改成 `10`。经常把一句话拆成好几条时，合并等待可以到 `1.5` 秒，最长等待仍用 `3` 秒。窗口拉得越长，普通闲聊越可能被送进主模型。

## 什么情况下会交给模型

称呼、@ 机器人、引用机器人，或者 `/`、`#` 这类原生唤醒，会打开本人的窗口。之后 90 秒内，这个人继续打字、补一句、发一张图，都不需要再叫一次。成功发出回答才重新计算这 90 秒；模型选择沉默、发送失败、答案被后来的消息盖掉，都不续期。

同一个人连着发的短消息会合成一批再问模型。默认停手 1.2 秒就提交，最多等 3 秒。一批最多 8 条、8000 字。单条本来就超长时，整条单独提交，不截断。

别人想插进来，必须落在机器人刚刚回答后的 20 秒里，并且只对得上一个正在进行的话题。下面三种算对得上：

- 用「我也」「其实」「确实」这类接话，并且碰到至少一个话题词。
- 连续说出至少三个字的话题，例如机器人刚谈过轨道电梯，另一人问「轨道电梯材料是什么」。
- 这句话是在提问，并且至少碰到两个话题词。两个词可以不相邻，例如「星河结局是什么」。

只碰巧用到两个分开的词，不算。机器人刚说材料强度不够时，「我今天材料交了，强度训练也结束了」不会叫模型。同时对得上两个人的话题时也不加入，免得串线。

通过这种方式加入的人，回答发出去之后有自己的 90 秒，但免唤醒只延续加入时的话题。「这种材料能造出来吗」「有多贵」「再详细说说」可以接着说；突然问火锅在哪里吃，会在本地丢掉，不调用模型，也不续期。要换题，重新称呼或 @。图片仍交给主模型看它跟不跟当前话题有关，所以窗口里的图片会调用模型。

没有明显词语衔接的改述，这套字面规则会漏掉。那时再叫一次名字就行。

自动候选每次只调用原来的主模型，由它决定回答还是沉默。沉默时插件要求模型只输出一个内部标记；这个标记不会发到群里，也不会写进聊天历史，更不会把窗口续上。所以自动候选不保证条条都有回复。

这些消息会在本地停掉，不叫模型：

- 明确 @ 了别人，或引用了别人。如果同时又叫了机器人的名字，仍然算在叫它。
- 重复投递的同一条消息。
- 「好」「嗯」「收到」这种收尾，除非机器人上一句是在问要不要继续。
- 配置的结束语。它只关掉说话这个人自己的窗口。

命令和固定功能先执行，不并进续聊，也不因为命令本身续期。`/reset` 和 `/new` 成功之后，这个群里的短时窗口会清掉。没有对应命令、最后仍走进聊天的 `/提问`，可以像普通唤醒一样打开窗口。

显式唤醒在容量不足时回到原生回答链路；容量拒绝不会使已经生成中的答案失效。发送失败或主动抑制的回答不续期，也不提交为已送达记录。折叠转发只在确认发送后使用 OutputPro 提供的正文锚点。

维护发布时，先核对线上 `main.py`、`engine.py`、`settings.py` 的 SHA256，并把已验证补丁合并到本仓库，运行回归后更新版本和 CHANGELOG；部署只上传明确的代码文件。线上有本仓库未包含的改动时停止发布，先完成合并。临时耗时观测代码不属于发布源码。

正在生成时又补来的文字，优先走 AstrBot 原来的同用户追加。已经执行的工具不取消、不重跑；没被这一轮吸收的内容进入下一批。原生追加只收文字，所以生成中途补的图片会等这一轮结束。新消息到达后，还没交给平台发送的旧答案会被压掉，不当作已经说过的话写进历史。已经发出去的消息撤不回来。

这个插件接管的回答会关掉流式输出，避免半句先冒出来。工具状态提示和分段回复仍看 AstrBot 自己的配置；这两项开着时，群里会多出中间消息。

重启、重载插件、会话被换掉，短时状态都会丢。某个用户的待处理批次如果异常挂了超过 10 分钟，也会一起失效。已经跑起来的工具不会被强行取消。

## 和别的功能怎么相处

插件按平台、机器人、群、用户分开记窗口。A 的 90 秒不会让 B 的闲聊变成候选，另一个群也不会串过来。它依赖群共享会话：每个人各有一份会话 ID 时，后一条消息会把这个群的短时窗口清掉。

场景感知、长期记忆、主动插话如果还开着，会另外决定要不要说话、要不要往提示词里加内容。那些不是这个插件的功能。全群开放问题仍由感知插件自己限频；那种一次性插话不会顺便打开 90 秒续聊。

每条自动候选都会多出一小段临时说明，放在系统提示里，不写进聊天历史。它提醒模型：这不是必须回答的唤醒，跑题或在跟别人说话时保持沉默。显式 @ 和称呼不附加这段说明。

## 自测

本地规则测试不需要安装 AstrBot：

```powershell
python -m unittest discover -s tests -v
```

`tests/integration_pipeline.py` 要在独立的 AstrBot 数据目录里跑。它会建虚构会话，并替换模型返回值和 QQ 发送端。不要对着正在使用的进程跑。它覆盖唤醒、命令、Agent、发送和历史；不能代替真实 QQ、多模态和联网搜索。

兼容点包括 AstrBot 4.28.1 / 4.29.3 的事件顺序、原生的同用户追加，以及消息上的 `_no_save` 标记。其他插件如果自己发送消息、提前把回答存进历史，或换了 Agent，需要单独看一次。

## 停用

关掉总开关，或把启用群列表清空，新的续聊就会停。重载或卸载会放掉还在等待的批次，不删除已有聊天记录，也不改人格和模型。安装时如果手动停过别的昵称入口，卸载后要自己加回去。
