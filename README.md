# 自然续聊

让 QQ 群中的下一句话接得上：用户用 @、称呼或原生唤醒发起聊天后，短时间内可以直接补充、追问和发图。插件先在本地过滤，再由原来的主模型回答或沉默，不使用额外判断模型或长期记忆库。

**0.1.0 正在验收，尚未正式发布。** GitHub Release 和市场收录状态以实际发布记录为准。

```text
甲：小村长你怎么评价
机器人：评价什么？
甲：电影《星河》最后一幕
机器人：……
乙：我也觉得星河的画面不错
机器人：……（可以参与，也可以沉默）
丙：今晚吃火锅吗
（不因此调用模型）
```

## 安装与启用

适用范围：AstrBot 4.28.1、OneBot v11 QQ 群、内置 Agent。首版版本声明限制在 `>=4.28.1,<4.29.0`，其他版本需另行验证。私聊和第三方 Agent 不接管。

正式发布后，可在插件管理中填写仓库地址安装：

```text
https://github.com/NovaTrailX/astrbot_plugin_natural_followup
```

在插件配置面板填写“启用群列表”。格式为 `平台实例ID:GroupMessage:群号`，例如虚构值 `qq-main:GroupMessage:123456789`。平台实例 ID 从 AstrBot 消息平台配置中获取。**空列表不启用任何群**。额外称呼默认也为空，按自己的机器人设置，例如“小村长”。

建议沿用群共享会话，开启原生发送者标识；插件会在未开启标识时为它接管的请求补充发送者身份。模型与人格沿用该群原配置。图片使用 AstrBot 已有多模态处理，没有新增识图模型。

若已有自动续聊或昵称唤醒插件，先停用它们对应的重复入口。不要同时用两套机制扩大自动响应范围。插件不会自动修改其他插件配置。

## 配置

| 配置键 | 默认值 | 用途与影响 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关闭后恢复原生触发。 |
| `enabled_groups` | `[]` | 按平台实例限定群；空列表不启用任何群。 |
| `aliases` | `[]` | 额外称呼；匹配句首或句末独立称呼，不匹配普通句中提及。 |
| `idle_seconds` | `90` | 本人空闲超时，10–300 秒；成功发送回答后续期。 |
| `join_seconds` | `20` | 群友加入窗口，0–60 秒且不超过本人超时；0 关闭。 |
| `debounce_seconds` | `1.2` | 同一人停止输入后等待多久合并提交，0–3 秒。 |
| `max_wait_seconds` | `3` | 最长收集时间，0–10 秒，不能小于合并等待。 |
| `image_followup` | `true` | 是否接纳免唤醒的图片补充。 |
| `user_batches_per_minute` | `8` | 每用户每分钟自动候选上限，不限制显式唤醒。 |
| `group_batches_per_minute` | `20` | 每群每分钟自动候选上限。 |
| `join_batches_per_window` | `2` | 每群每个加入窗口的新群友候选上限。 |
| `end_phrases` | 不用回了、先这样、不用回复了、先不聊了 | 精确结束本人窗口；忽略首尾空白、末尾常见标点与前置称呼。 |
| `debug_stats` | `false` | 记录原因、条数与耗时；不记录正文、账号或凭据。 |

三个候选上限均接受 1–120 的整数。非法配置会报错，不会静默改成更宽松的设置。

先使用默认值。消息密集的群可以将加入窗口设为 0 或 10 秒、每群自动候选设为 10；若经常把一句话拆成多条，合并等待可调到 1.5 秒、最长等待保持 3 秒。更长的窗口意味着更多普通聊天可能成为主模型候选，并不必然更自然。

## 具体规则

- 命令和固定功能先运行，不合并、不重放、不续期；没有匹配插件命令、最终进入聊天链的 `/提问` 可以开启窗口。
- 本人窗口内不要求固定句首词。明确 @ 或引用他人、重复消息、无需确认时的简单收尾优先在本地过滤。“好、嗯”在机器人询问确认后仍可接续。
- 新群友在加入窗口内，可以通过接续语加话题词，或直接复现足够明确的话题加入，不要求固定句首。例如机器人刚谈过“轨道电梯”，另一人直接问“轨道电梯材料是什么”也能成为候选。只匹配一个近期对话锚点时才接纳；单独赞同、仅碰巧重合一个二字词或归属不清时不自动加入。文字关联是保守规则，不是语义分类器。
- 通过相关插话加入的人，成功回答后获得自己的续聊时限，但免唤醒只延续加入时的话题。“这种材料能制造吗”“有多贵”等可接续，突然问“火锅在哪里吃”会在本地忽略，不调用模型、不续期。重新使用称呼或 @ 可以明确换题。图片沿用主模型判断是否相关。保守文字规则可能漏接没有明显词语关联的改述，此时重新唤醒即可。
- 自动候选沿用一次主模型调用决定回答或沉默。沉默不会发送、保存为聊天历史或续期；因此自动候选并不保证每次有回复。
- 同用户短消息最多每批 8 条、8,000 字。单条原消息超过上限时独立提交，不截断原文。每用户最多保留 4 个待处理批次，全局最多 128 个用户状态。
- 生成中追加文字优先走原生同用户 follow-up。已执行的工具不取消、不重复执行；未被吸收的补充进入下一批。原生追加只支持文字，所以运行中补图会等待前轮结束，再进入多模态请求。
- 新补充到达后，尚未提交平台的旧答案会被抑制，不当作已发言写入历史。已提交平台发送的内容无法撤回。发送校验只包装当前事件，管线结束即还原。
- 管理的回答关闭流式输出，中间说明等待最终回答；原生工具状态提示仍受 AstrBot 配置控制。推荐关闭工具状态提示和分段回复，以减少群内噪声。
- 重启、插件重载、会话改变或成功执行会话重置会丢弃短时状态。结束短语仅关闭本人。持续异常超过 10 分钟的本用户待处理状态也会失效；不强行取消已经执行的工具。

## 验证与限制

本地行为测试不需要安装 AstrBot：

```powershell
python -m unittest discover -s tests -v
```

`tests/integration_pipeline.py` 用于**独立的 AstrBot 测试数据目录**，会创建虚构会话并替换模型返回值及 QQ 发送端。不要在生产进程中运行。它验证真实框架的唤醒、命令、Agent、发送与历史保存管线；不替代真实 QQ、多模态模型和联网搜索验收。

兼容边界依赖 AstrBot 4.28.1 的事件生命周期、原生 follow-up 和消息 `_no_save` 标志。其他插件直接发送消息、提前持久化回答或接管 Agent 时，需要单独验证。公共 CI 验证独立规则与语法，不宣称等同于真实 QQ 验收。

## 停用与卸载

关闭总开关或清空启用群列表可停止新增续聊。插件管理中重载或卸载会释放等待批次与清理任务；不删除原生聊天历史，不改变人格和模型。若安装时手动停用了别的昵称触发入口，卸载后按需恢复那一项配置。
